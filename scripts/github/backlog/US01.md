## Acceptance criteria

- [ ] **Given** a user with a valid username and password, **when** she logs in, **then** she reaches the console home page; with a wrong password, an error is shown and no session is created
- [ ] **Given** the custom `User` model (AbstractUser), **when** an account is created, **then** it has exactly one role among ANALYST, CISO, ADMIN and belongs to an `Organization`; the password is stored hashed
- [ ] **Given** a CISO, **when** she opens an analyst page, **then** access is granted (the CISO inherits analyst permissions)
- [ ] **Given** an analyst, **when** she opens a CISO-only or admin-only page or API endpoint, **then** access is refused (HTTP 403)
- [ ] **Given** the administrator, **when** she uses the Django admin, **then** she can create accounts and assign roles; other roles cannot
- [ ] **Given** a logged-in user, **when** she logs out, **then** protected pages redirect to the login page
- [ ] **Given** a fresh database, **when** the demo data command runs, **then** the accounts `analyst1`, `ciso1` and `admin1` exist
